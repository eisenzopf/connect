# Agent observation profile (Gate 6)

G6-025 exposes reusable engine observations and a fresh-leg context preparation hook. The implementation is recorded in `patches/rvoip/gate6-agent-observations.patch` and pinned by `dependencies/source-lock.json`. The public API is in `rvoip_core::agent`, `rvoip_core_traits::agent`, `rvoip_core::operational_events`, and `ConnectionAdapter`.

## Source and correlation

`OperationalEvent` retains its existing ordered lifecycle stages. Its `connection_id`, `transport`, local `sequence`, capture time, and `correlation_id` identify one observation. Correlation is `obs.<stream UUID>.<sequence>` (ASCII, at most 128 bytes), unique across stream incarnations. It is neither a logical mutation ID nor a durable receipt. An optional `source_binding` contains the current Core Conversation, Session, Participant and connection generation at capture. An unavailable or retired binding is `None`; provider fields never supply missing Core identifiers. This binding describes the source and grants no future access.

`Connected`, `MediaActivity`, quality reports and provider status remain separate facts. A provider saying “connected” does not establish compatible or bidirectional media, decoded audio, endpoint receipt, or readiness of another connection. `capture_complete: false` explicitly declines a claim about complete connection/provider history. This does not weaken the factual lifecycle stage or replace the operational stream's sticky health and cancellation boundaries.

`OperationalEventKind::AgentObservation` contains `AttributedAgentObservation`. Core derives its Conversation, Session, Participant, Connection, generation and transport from the current connection binding and rejects another transport borrowing that ID. A provider `role: user` remains an `AgentSpeakerRole`; it cannot identify a human Participant in mixed caller audio. The provider call/event references remain separate optional data. Within a physical provider route, `local_sequence` distinguishes repeated observations, including identical provider event IDs. Global event correlation is supplied by the operational envelope.

The in-process `Event::AgentObservation` broadcast is best effort. Its global cross-crate projection includes only connection ID, kind and local sequence; it excludes transcript, arguments, results, context and provider references. Debug output redacts agent content and source identities. Consumers needing lifecycle ordering install Core's bounded operational receiver and monitor its health.

## Typed observations and bounds

`AgentObservationContent` distinguishes Transcript, Speech, Action, ProviderStatus, Unavailable and Gap. Transcript and speech observations retain missing fields and `Partial`, `Final` or `Unavailable` completeness. `Final` describes one provider observation; it does not promise complete history. Actions distinguish `Requested`, `ResultObserved` and `Unknown`. A reported tool result is not an engine transfer result. These events never dispatch an action or confer permission.

Validated immutable observations serialize to at most 65,536 bytes. Provider references are nonempty, control-free strings of at most 512 bytes. Local sequences and numeric speech turns stay within the exact JavaScript integer range, 1 through 9,007,199,254,740,991 for sequence. Missing sequence intervals are explicit `missing_before` metadata on the next accepted observation. All captured observations declare `capture_complete: false`, including final transcripts and an unknown terminal tail. No content is invented for gaps.

The Vapi adapter accepts at most 1 MiB per provider text event and 32 actions per event. It normalizes documented `toolCallList` and wrapped `toolWithToolCallList` data behind the adapter, without duplicate interpretation of alternate lists in the same event. Separate repeated frames remain separate observations. Invalid or oversized input is unavailable; an oversized action list does not publish a valid prefix. Missing optional capabilities are represented by default-false `AgentCapabilities`; parsing capability does not assert remote provider availability. The Vapi default is `Unknown` remote availability.

Both `callId` and `call.id`, when present, must match the actual provider route. A mismatch produces an unavailable observation before raw event publication, barge-in, or terminal handling; it cannot terminate the current call. Frames with no asserted call ID remain bound to their actual WebSocket route. Observation capture uses bounded `try_send`: a stalled observation consumer does not block the provider media loop. Known local loss is attached to the next accepted event, even with a one-slot queue. This does not promise lossless provider capture or an external provider's retry behavior.

## Fresh private AI context

`AgentContextInitialization` validates an explicit Conversation, Session, AI Participant, original logical operation ID, history watermark, history completeness and bounded source-labelled items. IDs use the frozen ASCII WireIdentifier alphabet and 128-byte limit. Context has at most 64 items, at most 16,384 bytes per body and at most 65,536 serialized bytes overall. Source/provenance labels and text are untrusted data, not instructions or grants.

`Orchestrator::prepare_agent_context(request, context)` is synchronous preparation. It verifies matching outbound Session/Participant, an open current Conversation/Session and current AI membership, then calls the adapter hook. The default adapter returns unsupported. The hook does not retrieve history, create a connection, allocate a provider route, contact a provider, authorize delivery, or mutate an existing call. The host must select an authorized history snapshot and enforce current authority at the actual effect boundary. Prepared metadata cannot substitute for those checks.

Vapi supports fresh origination with an explicit inline/override model containing provider and model strings. A saved assistant with unknown model, an existing-call attachment, or malformed messages is unsupported. Existing model messages are preserved. The adapter stores validated metadata in private call options and checks Session/Participant again before origination. At actual create-call serialization it adds a fixed system data envelope to `assistant.model.messages` or `assistantOverrides.model.messages`. The local HTTP fixture verifies the actual serialized payload and zero provider IO during preparation. It does not prove that a remote provider applied context or that a model followed it.

## Connect wire and HTTP boundary

This is the reusable engine primitive required by G6-025. The frozen public `session.observation` family remains specified by [Connect UCTP](connect-uctp.md) and `schemas/uctp-envelope-2.schema.json`; its correlation, audience and canonical data projection are owned by the service integration tasks. G6-037/G6-038 still install durable current authority and service projection. The existing HTTP event reference is [openapi-events.json](openapi-events.json). This engine patch adds no HTTP endpoint and does not claim that the new in-process event is already a durable public journal event. HTTP authentication, audience filtering, replay and delivery authorization remain required at their existing service boundaries.

Vapi format references: [client tool calls](https://docs.vapi.ai/tools/client-side-websdk), [server events](https://docs.vapi.ai/server-url/events), and [WebSocket transport](https://docs.vapi.ai/calls/websocket-transport). Qualification uses isolated HTTP/WebSocket fixtures on local macOS arm64. Live providers, named remote rehearsals, Linux, native/browser end-to-end profiles, full media quality, durable Connect projection and Gate 6 acceptance remain separate checks.
