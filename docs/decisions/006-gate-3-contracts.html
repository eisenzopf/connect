Decision 006 · Gate 3 · October 9, 2026

One durable conversation.
Disposable live media.

Connect owns application authority and history. rvoip owns live cross-transport orchestration. UCTP carries the standard session, connection and stream lifecycle; connect-control/1 adds durable application operations without replacing UCTP.

Accepted for the implemented local Gate 3 core · completion audit closed with qualified changed-profile evidence

Ownership

Noun Durable owner Live projection Restart rule
Conversation Connect SQLite, persistent by default Exact namespaced ID in rvoip History survives; projection is rebuilt

Stream Negotiated metadata and provenance rvoip media stream/router Always renegotiated

Lifecycle

developer creates cid once
  → session.invite / session.accept under that cid
  → authenticated UCTP resolver rechecks credential + membership
  → Connect projects canonical cid/sid into rvoip
  → connection.offer binds an authorized stream
  → connection.ready advances durable Session to ready
  → media datagrams flow; messages and artifacts continue concurrently
  → connection loss records interruption
  → session.end closes the bounded leg, never the Conversation

Application profile

The existing connect-control/1 profile gains additive typed operations for sessions, context, availability and artifacts. Old clients continue to use the earlier operation set. Incompatible wire changes require a new profile.

Session authority

The wire Session ID resolves into connect:<installation>:<sid>. Every bind and refresh rechecks the current credential, conversation membership and nonterminal Session state. Cross-peer reuse cannot alias global media state.

Context

context_view returns an authorized, chronological selection with source IDs, actor IDs, journal sequence watermark and explicit omission count. The current bound is 32 KiB. A new Session does not create a new Conversation.

Availability

Available and unavailable are expiring observations. Expired or absent data returns unknown. A preferred route is an expiring hint and never triggers automatic contact or fallback.

Files and limits

Gate 3 operations use begin, offset-checked append, digest-verified finish, resumable get and explicit delete. The frozen local profile is 16 MiB per artifact, 256 MiB per installation and 32 KiB decoded chunks. Current authorization is rechecked on every operation. Managed external blob storage, current-authority checks, manifest-coupled backup/restore and bounded orphan cleanup are implemented. Full lifecycle pressure and deletion qualification remains tracked in G3-027.

Verified now

  • A saved-assistant Vapi route attaches through the pinned rvoip duplex WebSocket adapter. A loopback provider proves audio in both directions, bounded context injection and a durable delivery outcome without account effects.
  • HTTP and native QUIC operations observe the same session, context, availability and artifact state.
  • Python and TypeScript helpers carry raw PCMU over real native UCTP/QUIC sessions; browser code uses an explicit WebRTC-only entry.
  • Local SIP and authenticated WebRTC routes enter through configured authority, bridge duplex audio to the same fake Vapi agent and keep their bounded Sessions inside the durable Conversation.
  • Artifact bytes are integrity checked in managed storage and restored with their database metadata through backup manifest v2.
  • The high level rvoip Orchestrator receives the canonical conversation/session projection; Connect records ready and interrupted transitions.
  • Earlier live Vapi, Telnyx PSTN and browser evidence remains recorded. The completion audit found queue defaults above the frozen media budget and missing explicit RTP reordering.
