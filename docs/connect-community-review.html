Five improvements before handoff.

01 · Reliability

Deadlines and shutdown mean what they say.

Python now bounds partial helper writes and reads. Failed helpers close and are reaped. Worker shutdown reports failures and panics, drains siblings, and aborts stalled work. Cancellation cannot detach owned workers.

02 · SDK design

Small modules. Explicit results.

Python and TypeScript separate operations, validation, errors and transports. TypeScript exports named result types. Both validate profile, correlation and payload shapes, cap response sizes, refuse redirects and preserve mutation IDs across uncertainty.

03 · Extensibility

An adapter does not need a database.

The new connect-connector-api crate contains provider request and observation types. Server workers map durable jobs to that interface. A compiled echo example shows the boundary; dynamic plugin loading is not claimed.

04 · Protocol

All twelve operations are documented.

Gate 2 delivery and call-control operations now join the wire contract. Shared result fixtures cover all outcome kinds and inbound call events. Rust, Python and TypeScript validate the same examples.

05 · Contributor experience

A reproducible place to begin.

Contribution, architecture and connector guides accompany a pinned GitHub Actions workflow. Source checks need no provider keys. Archived-binary upgrade and installed-package checks remain explicit local release requirements.

Two telephone paths. Separate acceptance.

Verified · Gate 2

Connect controls the call.

Handset ↔ Telnyx ↔ Vapi

Connect provisions the route, starts and ends calls through the SDK, observes provider status, and journals the conversation. Outbound: five human and five assistant turns. Inbound: you confirmed answering; provider records two human turns and one assistant turn.

The assistant can answer while Connect is offline. Audio-quality metrics were not measured.

Not implemented · Gate 3

Connect carries the audio.

Telnyx SIP ↔ Connect ↔ Vapi WebSocket

This requires an actual media bridge and end-to-end bidirectional audio tests. Native QUIC datagrams and browser WebRTC have separate codec/lifecycle acceptance. Neither a purchased SIP trunk nor a QUIC probe qualifies the complete route.

What this alpha does not claim.

  • Live SMS delivery or signed carrier callbacks: deferred until approval, with local implementation/fixtures retained.
  • Connect-carried SIP/PSTN, native assistant QUIC media, or browser WebRTC audio: Gate 3.
  • Dynamic presence/contact preferences: B-001 remains an explicit feature decision, not a dropped requirement.
  • A released MCP integration, extra assistant connector, file/video implementation, or finished human client.
  • Production hardening, independent security audit, automatic worker supervision, cross-platform qualification, public server ingress, or published npm/PyPI/server packages.

Schema remains 6. Local upstream patches remain pinned and digest-checked. The connector interface is an experimental Rust extension point and can evolve before a stable release.
