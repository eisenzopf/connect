Build with Connect / Parley

Grow a conversation into coordinated follow-through.

The example owns travel data, prompts and approval policy. Its communications use Connect's public client boundary.

The progression

  1. Chat and context: start one Conversation and send an attributed task to the assistant.
  2. Voice: speak with the assistant, finish that Session and gather an attributed itinerary from the booker.
  3. Organizer contact: ask privately for call permission, distinguish delivery from reply, then invite the organizer.
  4. Private consultation: retain the organizer leg while consulting the owner. Decline returns without takeover.
  5. Human takeover: require current owner consent and the assistant action before transferring responsibility.
  6. Device movement: keep the current leg usable until the selected phone confirms the configured DTMF digit and media is ready.
  7. Follow-up and recovery: end voice, retain history, approve an exact proposal and send separate updates under saved logical IDs.

What you can inspect now

The shared scenario and fixture guide covers seventeen stages, an optional observer, two consultation paths, synthetic speaker markers, local SIP/RTP and HTTP SMS fixtures. Fixture model output is explicitly simulated. Fixture/live bindings select the same stage definition; selecting a path does not satisfy consent or media gates.

The installed public-SDK app and executed tutorial checkpoints are not complete. G6-072–G6-080 build and qualify the application; G6-084 provides the runnable progressive tutorial afterward. This outline is not a completed application rehearsal or authorization to contact a provider.

Prepare to adapt it

Read the shared model, consultation and handoff, and SDK/reference boundaries. No application should read Connect's store or construct an rvoip bridge.
