    From the repository root, use the existing commands below. They do not qualify new Gate 3 behavior until its tests exist. The historical upgrade binary/manifest must be available for the baseline runner; consult the developer guide if it is missing.

    bash scripts/prepare-dependencies.sh
cargo check --locked --workspace
bash scripts/format.sh --check
bash scripts/check-local.sh
bash scripts/check-gate-2.sh
  2. L1 · Isolate

    Start a new local installation.

    After building, use a new private directory and unoccupied loopback ports. Do not reuse a personal installation or erase state to fix a failed test. The commands below exist today; Gate 3 media/transfer configuration is added by G3-008 and documented by G3-034.

    cargo build --locked --workspace
target/debug/connect init --directory .local/gate-3-review --example review-loop --bind 127.0.0.1:4438
target/debug/connect serve --config .local/gate-3-review/server.toml

    In a second terminal, check target/debug/connect health --config .local/gate-3-review/operator.toml. Inspect the generated protected config; never paste keys into documentation.

  3. L2 · Offline

    Qualify without provider effects.

    G3-031 creates scripts/check-gate-3.sh; it does not exist yet. It must provision only isolated local fixtures, emit per-phase results, bound waits and clean up only its own processes. Cover native audio, SIP/WebRTC peers, context, files, SDK parity, revocation and recovery. No keys, tunnels, number purchases, SMS or telephone calls in this runner.

  4. L3 · Reachability

    Prepare a separate live rehearsal.

    Use private TELNYX_API_KEY and VAPI_PRIVATE_KEY configuration and the existing isolated assistant/number/trunk where appropriate. Record resource IDs and a route-restoration snapshot privately. Verify the chosen SIP authentication, NAT/advertised media addresses and browser ICE behavior. The server remains local; HTTP callback reachability alone is not SIP/RTP reachability.

    This plan performs no account mutation or public-ingress setup. Live qualification is separately invoked by the operator within existing authorization; automatic local checks cannot trigger it. If the network or account cannot support the planned path, mark its task blocked and record the needed change.

  5. L4 · Live proof

    Show the media and context paths.

    Run G3-017, G3-020, the live part of G3-022 and G3-029. Use an authorized handset and announce the outbound caller ID first. Verify both audio directions and continuity, then restore any temporarily changed direct route. Retain redacted metadata and human observations; do not publish raw credentials, private control URLs or unnecessary call content.

  6. L5 · Recovery

    Preserve the database and artifact bytes.

    Use generated schema-6 state to test migration and an isolated current snapshot to test recovery. G3-027 extends backup to include a consistent set of blob references and bytes. Restore into a new directory on different ports, verify original history/receipts/artifacts, and rehearse rollback with the matching old binary and pre-upgrade backup. Never delete or overwrite the source installation.

  7. L6 · Package

    Install the candidate as a reviewer would.

    At a clean candidate source revision run bash scripts/package-local.sh, then python3 scripts/check-package.py /absolute/path/to/candidate-directory. G3-033 must extend those existing scripts for new media/client/file assets first. Separate source qualification from installed-package qualification; neither substitutes for recorded live routes.

  8. L7 · Handoff

    Publish evidence into the repository.

    G3-035 creates the redacted local review report under docs/evidence/gate-3/. Record exact source/patch/profile/schema versions, hardware, commands, thresholds, measurements and every passed/failed/blocked/skipped criterion. Leave private raw material under .local/. No remote deployment or public release is implied.

Keep the plan usable as work progresses.

  1. Assign an owner, mark the item in progress and record any design change before implementing dependent work.
  2. Add concrete source revision, command/result and redacted evidence references. A test filename or a successful compile alone is insufficient.
  3. Mark done only after all dependencies and the stated proof pass. Reopen dependents before reopening their completed prerequisite.
  4. Save updated HTML and replace this repository file; review the diff and commit it with the corresponding work. Exported status JSON is a snapshot, not a second status authority.
  5. Keep the acceptance map, product plan, roadmap and coverage current when scope changes. Required deferred/blocked work prevents closure unless the owner explicitly changes scope.
  6. Preserve numbered IDs and earlier evidence. Finalize A3 criteria only from qualified results; the checklist cannot attest code quality by itself.
