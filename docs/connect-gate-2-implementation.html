04

What this proof establishes.

AreaCurrent behavior
Provider effectsLocal acceptance is durable. Remote SMS acceptance is separate from handset delivery. An interrupted external mutation is uncertain and never automatically repeated.
BindingsExplicit operator routes bind an identity and provider target to a conversation. SMS sender/receiver pairs are unique. New conversations require a route binding; universal discovery and dynamic agent routing are future work.
Language clientsPython and TypeScript native mode use the Rust QUIC helper. HTTP mode uses the loopback HTTP API. No browser-native QUIC, npm/PyPI publication or additional host qualification is claimed.
State upgradeSchema 6 adds discovery watermarks and attributable end intent to inbound voice state. Existing schema 1–5 installations need a fresh verified backup and the migrate command on a stopped installation. Existing messaging credentials do not acquire voice permissions; issue an explicit voice credential. Gate 1 snapshots and packages remain unchanged.
Voice resourceThe dedicated number and SIP connection exist. Voice work is tracked below: provider provisioning, durable SDK call control, telephone audio, native QUIC datagram audio and WebRTC are separate checks. None is inferred from successful resource creation or chat.
Human controlScoped credentials, explicit routes and observable delivery state are implemented. This gate does not introduce per-action approval prompts or the proposed permission-management UI.

Provider source references: Telnyx Rust library, Telnyx callback verification, Vapi chat API, Vapi/Telnyx SIP setup.
