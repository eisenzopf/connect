Build with Connect / Concepts

One model across communication channels.

Keep durable conversation state, live interaction and current authority distinct.

Shared vocabulary

Shared Connect terminology
ConnectThe communications server and public SDKs. Applications use this boundary instead of constructing media bridges or calling provider communications APIs.
UCTPThe shared control and media protocol. Protocol conformance is separate from a successful SDK request.
rvoipThe reusable protocol, transport and media engine beneath Connect. It is not an application-side bridge API.
ParleyThe reference coordination scenario. Its goals, travel data, prompts and business approval policy belong to the example.
ConversationThe durable container for Participants, Messages and Sessions. Ending voice does not by itself close it.
ParticipantAn Identity's appearance in one Conversation. Membership, role, Session presence and current permission are separate.
MessageAn attributed durable communication with an explicit recipient audience. Acceptance is distinct from delivery, reading and a reply.
SessionA live interaction inside a Conversation. Acceptance and negotiated media readiness are different observations.
ConnectionA Participant's negotiated leg in a Session. A device move replaces this leg while preserving the Participant.
StreamA negotiated audio, video, screen or data flow carried by a Connection. Transport connectivity alone does not prove usable media.
Identity / Device / EndpointA durable tenant-scoped entity; its physical or software device; and a provisioned reachable binding with capabilities, verification and freshness.
OperationAn observable logical action with a saved ID. An uncertain effect is recovered under that original ID and current authority.
Handoff / device movementHandoff changes Participant responsibility and the selected media audience. Device movement changes one Participant's leg. Both preserve the retained remote leg when committed.

Follow the contract

This terminology map follows the current model decision and canonical protocol mapping. The earlier baseline retains its original scope; accepted Gate 6 lifecycle changes are described in the current decision.

Application business approval and Connect authorization are separate. Preserve saved logical operation IDs through uncertainty; current authority is checked again on replay. Neither a label nor a copied handle grants permission.

The full lifecycle concepts guide, contract-traced diagrams and failed-move walkthrough are G6-083 work. This page provides the shared vocabulary and its source map.
