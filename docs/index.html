04

Keep the documents together.

A developer’s change is complete when its public contract, sample, checklist and evidence agree.

  1. Update the v0.1 contract only when the product scope changes.
  2. Review the affected gate’s product/delivery plan before adding a new implementation commitment.
  3. Preserve implementation item IDs; record changed scope and real verification evidence.
  4. Update SDK instructions and compatibility when interfaces or schemas change.
  5. Retain archived evidence with its original revision and tested environment.
  6. Sync the reviewed documentation to Rudeless’s Connect docs surface and match the public project language.
