Read the project in this order.

  1. Product & technical brief

    The product promise, v0.1 scope, interfaces, boundaries and release acceptance. This defines what we are trying to deliver.

  2. Product experience design

    Give an agent presence. Make an app reachable. The intended first-run journeys and SDK/tool experience; illustrative commands remain design sketches.

  3. Technical readiness & reuse map

    What rvoip, Parley, Bridgefu and Thelve can contribute, the integration gaps, and experiments E1–E8. This is dated source research, not a current completion report.

  4. Product delivery roadmap

    The missing bridge between vision and implementation: gate milestones, dependencies, every promised capability, accepted directions and remaining decisions, SMS return path and the full v0.1 finish line.

  5. Gate product plans → implementation plans → evidence

    Read the acceptance criteria before the task checklist. Treat test and live records as the basis for completion claims.

One change, consistent documents.

  1. Change the product brief only when the intended promise changes.
  2. Update the experience design when user behavior changes.
  3. Update the roadmap and structured coverage when delivery assignments or dependencies change.
  4. Update the relevant gate plan and numbered checklist when acceptance or implementation changes.
  5. Attach dated evidence; preserve earlier results and stable IDs.
  6. Keep this index pointing to current plans and clearly labeled historical material.
