Build with Connect / Start

Start with messages and retained history.

Use the current ARM review kit to exchange a local message and reply, then recover the same history after restart.

Install the current ARM review kit

Use the matching unpublished Gate 6 review kit for macOS 15+ ARM64 or Ubuntu 24.04 ARM64. Have Node.js 22.16+ with npm, a Chromium browser and an owned writable directory. Ubuntu also needs libopus0 and libssl3t64. No source checkout, compiler, model or provider account is needed.

Check the supplied archive checksum, then run these commands in a new directory. Replace the archive path with your reviewed kit:

mkdir connect-first
cd connect-first
tar -xzf /path/to/your-kit.tar.gz --strip-components=1
node verify.mjs
npm install --offline --ignore-scripts --no-audit --no-fund --no-save --cache .local/npm-cache ./sdk/rudeless-connect-0.1.0.tgz ./sdk/dependencies/*.tgz
export PATH="$PWD/runtime/bin:$PATH"
node app/run.mjs

Open the printed loopback URL. Private setup and credentials stay in .local/parley on the backend. Read the complete quickstart and troubleshooting.

Exchange a message and reply

  1. Keep Owner as your perspective. Under Choose people, clear Assistant (simulated), select Organizer and choose Create conversation.
  2. Send Hello Connect to Organizer and wait for its completed operation.
  3. Select the Organizer perspective and Conversation 1, then send Hello back to Owner.
  4. Return to Owner and Conversation 1. Both messages should appear once.

The participants are local synthetic people; you send the reply yourself. No model or communications provider runs.

Retain history after restart

Press Ctrl-C and wait for the command to exit. In the same directory, repeat:

node app/run.mjs

Reload the printed URL and open Conversation 1 as Owner. Both messages remain; original setup and operation IDs are retained automatically. Ctrl-C again joins the app, server and helpers. Continue with voice and video.

The automated clean-consumer rehearsal and its limits are recorded in the quickstart evidence. Three-developer usability and the later full Parley journey remain separate qualifications.

Using the published v0.1 release

The published macOS ARM64 release uses an earlier API. Follow its installation guide, setup demo and release notes with that release's own executable. Keep its instructions separate from the current review kit.

Work with the current source

Use signed initialization and serving, the typed Rust SDK and explicit application configuration. Native and HTTP configurations are distinct; neither silently selects a fallback.

The review-loop initialization preset currently enrolls communication identities; the earlier review-loop app still awaits its signed SDK migration. Follow the workspace build/check guide for development, rather than running the published demo against an unrelated source binary.

Continue with your app

Learn the model, then explore voice and video or the Parley progression. Media readiness requires actual decoded media; a command ACK or an answered call alone does not prove it.
