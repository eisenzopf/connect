Reuse before reinvention

What Parley already solved.

Parley contributes both useful product patterns and concrete rvoip fixes. Keep the library improvements reusable; keep Connect’s durable contract and provider semantics explicit.

Reviewed pinned Parley revision 22509d4df4cbf8dccd2ac7d35d0ac3becc724ceb. Findings below describe source behavior; they do not claim Connect’s future voice paths have been proven.

patches/rvoip/conference.patch

SIP/RTP interoperability fixes

patches/rvoip/conference.patch

The aggregate patch includes late SDP RTCP destination updates and negotiated RTCP mux behavior. Its Vapi adapter diff adds safe writer and barge-in diagnostics; it does not change audio framing.Already present in the dependency tree, but Connect Gate 2 does not exercise the SIP/Vapi audio path. Qualify those fixes in the voice gate. The standalone RTCP patches overlap the aggregate and must not be applied twice.
Vapi chat fallback and output retry

src/vapi_chat.rs

Parley can issue a second chat creation after the first call errors or yields unsuitable output. That may be practical for a demo but can duplicate unknown provider effects.Do not copy into Connect’s durable outbox. Connect uses zero automatic retries and preserves uncertain outcomes for reconciliation.
Browser JavaScript transport

web/widget/src/uctp.ts

Parley’s browser client uses WebSocket URLs. Its conversation-control application profile is useful evidence, but conference/tenant behavior belongs to Parley.Reuse protocol concepts rather than presenting this client as a native QUIC SDK. Connect’s Python and Node SDKs currently reach QUIC through the Rust helper; HTTP/JSON is a separate option.

The envelope is sufficient; the profile needs rules.

Use UCTP cid for Conversation correlation and in_reply_to for wire exchange correlation. A logical mutation ID survives reconnects; provider event/message/chat IDs remain separate. Connect now writes cid and rejects a supplied header that conflicts with its payload. Older envelopes without cid remain compatible.

Callbacks commit canonical messages to the same journal read by UCTP clients. Provider delivery changes are currently visible through provider_status polling. They are not yet resumable push events. Adding a delivery-event vocabulary, persistence and SDK consumption together is the next useful interface improvement.

Local qualification: 53 workspace tests and doctests, strict Clippy, SDK parity, crash replay, backup/restore, migration and independent example recovery passed. Synthetic signed provider fixtures and live Vapi chat are distinct evidence. Real handset SMS and SIP audio remain unverified.

Upstream direction

rvoip-core should expose the aggregate server/client interfaces for authenticated application profiles, correlated requests, unsolicited event subscriptions and owned shutdown. The UCTP substrate already carries these messages. Connect should not need separate application plumbing for each transport.
