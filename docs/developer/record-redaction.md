# Selective record redaction and retention

G6-027 remains in progress. `VconRedaction` freezes the original operation, exact location/body/manifest/revision and bounded source selections. Content redaction replaces payload with explicit unavailable metadata. Metadata redaction also clears source identity/audience/provenance and known dependent content. Source IDs remain stable and affected revisions advance. Recording-set relationships and private producer references are updated consistently.

Core memory and Postgres stores serialize redaction with returned record reads and deletion. A mutation waits for held readers; old handles fail after its CAS. Exact original replay returns its historical local fact even after another mutation or deletion. Changing a selection or reusing a redaction operation as deletion conflicts. The fact contains no source body and grants no read or replay authority. The host must retain current mutation authorization and persist its original operation. Local redaction does not claim provider erasure.

`retention_action` selects expired metadata/content under a protected read and returns the frozen redaction or whole-document deletion intent. Release the record read before awaiting its writer, while retaining current authorization. Reuse that exact original intent after uncertainty. The backend physically replaces expired bytes and manifest data; a persisted unavailable state is validated against actual canonical tombstone bytes. It cannot hide retained content. Already cleared content is not selected repeatedly. A full-document metadata limit uses deletion. This is a caller-driven primitive; Connect journal installation and retention scheduling remain required.

Unavailable views use a conservative metadata allowlist. Unknown flattened extension fields cannot become an alternate channel for expired or redacted content. Metadata tombstones are withheld from public projections, and unrelated retained source content remains available under its original current audience checks.

The fresh Postgres contract is `rvoip-vcon-records-v3`, with atomic body/manifest/revision and local mutation facts. Manifest version 2 requires explicit source availability state. Existing incompatible/partial schemas are refused. Back up existing state and explicitly initialize a fresh store when changing profiles; no automatic historical migration or reset is performed. The engine retains at most 4,096 redaction facts per record and refuses new redactions at capacity without evicting replay facts; whole-record deletion remains possible.

Run `python3 scripts/check-gate6-record-redaction.py --local-postgres` for the isolated local profile. Its cases exercise source/dependency removal, unrelated source preservation, old-handle refusal, real blocked delivery, cancellation before commit, loss after actual commit, changed-intent refusal, recovery after later deletion, independent retention and unknown-extension refusal. The temporary local database lane additionally exercises held row custody, source CAS and recovery through a fresh adapter. Raw logs/private scratch remain under ignored `.local/`.
