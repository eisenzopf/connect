# Persisted record sources and protected views

G6-027 remains in progress. This increment implements the source index and protected projection required by [the record contract](../../contracts/connect-records.md). Source capture integration, selective redaction, owned finalization/recovery and canonical fetch/delivery still have to complete that contract.

`VconRecord` stores canonical bytes with a complete `RecordManifest`. Every document, party, dialog, analysis and attachment has exactly one source rule. Rules retain stable source IDs/revisions, an explicit frozen audience or named policy decision, capture policy, dependencies, metadata/content retention and source provenance. Producing Participant and provider speaker role are separate data. Partial/final completeness and known local gaps do not establish complete history or permission.

`VconRecord::new` validates the whole record and source coverage before storage. Manifest decode validates bounds and normalizes source ordering; it cannot bypass construction checks. Limits are 16 MiB per record, 1 MiB per manifest, 4,096 sources, 256 audience Participants and 64 declared dependencies per source. An unattributed raw builder record receives empty source audiences, never a guessed Session-wide grant. This preserves private data for explicit later classification without inventing a public audience.

Storage publishes body, manifest and revision atomically. `VconHandle` binds both exact body and normalized manifest digests. A protected read returns the same revision's immutable source index under its retained backend reservation. Deletion clears the local manifest with the body and preserves only its factual mutation reference. The optional database schema has a fresh versioned contract; existing incompatible stores are refused without historical data migration.

`RecordViewRequest` binds exact owner scope, viewer, document UUID, revision, both digests and correlation. `RecordViewControl` is trusted backend composition: its lease must hold current credential/resource/source authorization, derive decisions under the same guard and retain it through actual delivery. It must not reacquire a reader behind its queued writer or wrap a stale boolean. Public IDs and source labels cannot create this authority.

`RecordProjection::prepare` owns both the stored read and that current policy control. It intersects current grants, frozen source audience, retention and source dependencies. It remaps all supported canonical Party/Dialog/Attachment/Analysis references, including transfer and recording-set relationships. Hidden or unavailable dependencies suppress dependent content. A mixed source is omitted as a whole rather than claiming its bytes were redacted by removing a Party. Unavailable media becomes schema-valid metadata; an original provider URL is withheld unless the current trusted media-reference hook supplies an expiring endpoint that still checks authorization on retrieval.

The final view is validated and hashed over its exact bytes. It does not advertise the original full-record digest or signature. Source IDs/revisions and permitted provenance accompany explicit omissions, unavailable content and best-effort capture. Private producer identities and connection details are not copied when the corresponding Party is hidden. Retain the projection through the response write; `view()` checks cancellation, deadline, current source decisions and expiry again. Body bytes and digests grant no future access.

`python3 scripts/check-gate6-record-projection.py` exercises persisted manifest reconstruction, forged-manifest refusal, public/private source separation, dependency rewriting, independent retention, current-policy/storage guard lifetime and existing engine/voice/export regressions. The independent JSON-schema export check validates a generated view against the pinned upstream fixture. The optional live database test is compiled and skipped by default. Add `--local-postgres` to run it in a fresh bounded local Docker fixture using an existing cached image; the helper never uses an existing database or pulls an image, and removes its own container/network. The explicit database lane records its exact image, limits, test and cleanup separately. Configured signed-source verification, media URL endpoints and public canonical service delivery are not qualified by these tests alone.

This adds no public HTTP route. The current public references remain [Connect UCTP](../../contracts/connect-uctp.md) and [the event HTTP reference](../../contracts/openapi-events.json).
