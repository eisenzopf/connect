# G6-024 media primitive qualification

This procedure maps the approved G6-024 engine contract to current-source behavior checks. Application Store/journal/SDK installation, Linux hosting, live browser interop, remote/provider profiles and the complete Gate 6 acceptance criteria retain their assigned downstream tasks. They are not established by local engine fixtures.

| Requirement | Current behavior evidence |
| --- | --- |
| Cross-runtime framing | The Rust checked APIs and actual browser fixture module on Node execute the shared eight valid and 31 invalid vectors. Complete RTP, nonzero physical handles, independent outer/RTP sequences, endian boundaries, extensions, padding and truncated inputs are checked. |
| Stream identity | Peer-router public tests check nonzero monotonic handles, no reuse after retirement, exact Session/Connection indexes, atomic reservations, wrong owners and shutdown. Signed native scope/retirement regressions exercise the live bindings. |
| Decoded audio | Actual signed QUIC and WebTransport source and recipient peers negotiate PCMU, PCMA and mono Opus. Encoded sine samples cross Core and decode with the negotiated sample count/rate and measured tone frequency. Source RTP sequence wraps. |
| Decoded camera/screen and fragmentation | Source peers use a fixed 1400-byte QUIC MTU; recipient peers use a fixed 1200-byte MTU, with path-MTU discovery disabled. Signed offers and the actual signed subscription command precede media. Real generated VP8 frames are RTP-packetized, cross Core, are refragmented to the physical recipient budget, and independently decoded by FFmpeg. Camera and screen each reproduce the source's three moving-frame pixel hashes. A lost source fragment leaves a visible RTP gap; subsequent complete keyframes decode. |
| Reliable data | Actual signed QUIC, WebTransport and WSS exercise text, JSON and binary formats. Unicode and binary bytes retain the original operation/message IDs and metadata. Invalid UTF-8/JSON produce no recipient message; later valid input succeeds. Existing ordering, audience, backpressure, quota, cancellation and uncertain-write suites repeat. |
| Failure/recovery and deadlines | Real native input covers malformed/truncated RTP, wrong version/payload/handle, empty audio and oversized video. Malformed VP8 descriptors produce no target packet. Valid audio exceeding the recipient datagram budget by one byte is dropped whole. Holding an admitted packet beyond the engine's 200 ms window refuses forwarding; a later valid packet decodes. These are locally observed queue deadlines, not inferred remote capture times. |
| Feedback and quality | Current interceptor NACK/RTX and RTC repair/owned-IO regressions repeat. The default WebRTC audio profile remains TWCC; optional registered Opus/NACK tests do not claim live-browser negotiation. Actual signed native quality cases verify elapsed intervals, per-physical-peer accepted/sent RTP counts, idle zeroes and omission of unmeasured loss/jitter/RTT/MOS. Counters describe admitted RTP and local submission, not codec correctness or remote playback. |
| DTMF | The complete received-source/Core/native/SIP/SRTP suite repeats: actual provenance and first-packet timing, original operation, exact live endpoint, independent current source/recipient permission and actual IO custody. Raw hints and ordinary media permission cannot schedule a signal effect. |

Run `python3 scripts/check-gate6-media-profiles.py`. It prepares pinned dependencies, checks formatting, builds the selected targets in one feature graph, records exact executable hashes, executes the matrix above, validates browser vectors and generated media, checks the locked Connect server, and verifies unchanged source inputs. Generated IVF, measurements, raw logs and executable archives remain under ignored `.local/gate-6/`. Skips and failures are not passes. Earlier component reports remain historical; their totals are not combined.

The authoritative task status and final report are in the Gate 6 implementation plan and `docs/evidence/gate-6/media-profiles.json`. Source preparation 96 adds test profiles and fixture configuration over frozen patch95; existing media algorithms are reused rather than replaced. Publication remains separate.
