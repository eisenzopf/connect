# Session record finalization and original-document recovery

G6-027 remains in progress. Ending a Session now freezes its original canonical record before attempting storage. The Session's local finalization entry owns the exact immutable bytes and manifest. `end_session` emits the Session outcome, then owns one bounded store attempt; it starts no detached record task. The record always includes a typed metadata outcome. Default message/transcript capture is disabled; an explicit installation policy can select source content under its own audience and independent retention.

`session_record_status` reports capturing, pending, ready, unavailable capture, or an unknown store outcome. Backend errors, cancellation and the two-second deadline cannot prove that a write did not commit. The status retains that uncertainty and the original record. Invalid raw capture is excluded and the record keeps an explicit metadata outcome without those invalid bytes. A ready record alone never implies that audio was recorded, that a caller may view it, or that anyone received it.

`retry_session_record` checks exact Tenant/Conversation/Session ownership and retries the same frozen document. Calling `end_session` again also retries its record without emitting another Session end. Concurrent attempts serialize per Session; independent Sessions proceed. A successful original write emits one local readiness hint. Mutating a retained old builder cannot alter the frozen retry. The host must enforce current authorization on each invocation and derive durable state from its journal.

Both Core memory and Postgres stores bind creation to the original document UUID, owner, bytes and manifest. An identical retry recovers the original live revision-one handle. Changed body, manifest or owner conflicts; retry after deletion cannot recreate bytes. Postgres commits creation and its checked binding in one transaction, and a fresh adapter can recover the exact original write after a lost response. Read and deletion reservations continue to apply.

The finalization registry is process-local. It drops its retry body after a confirmed exact write and retains unresolved original records until retry or Orchestrator drop. It provides caller-owned cancellation/retry, not a restart journal for pending capture. G6-037/G6-038 still install Connect's durable Session/operation authority. Complete connection lineage, media/provider-reference and conversation-only message capture mapping, physical retention/selective redaction, configured signed-source verification and canonical fetch/delivery remain required before G6-027 closes.

Run `python3 scripts/check-gate6-record-finalization.py --local-postgres` for the isolated local profile. It exercises the actual Orchestrator with store failure, cancellation after a real commit, concurrent retry, a stalled write alongside an independent Session, invalid capture, fabricated handles, and empty metadata-only records. The selected Postgres fixture uses its own temporary database and verifies exact replay through a fresh adapter, changed-intent conflicts and no resurrection after deletion. The fixture does not qualify an existing or remote database, process-crash capture recovery or Linux x86_64 hosting.

No HTTP route is added by these engine primitives. Public transport references remain [Connect UCTP](../../contracts/connect-uctp.md) and [the event HTTP reference](../../contracts/openapi-events.json).

Explicit source capture uses the actual frozen addressed-message ingress and current attributed agent event path. Messages intersect the installation selection with sender and send-time recipients; Session membership cannot widen a private message. Agent capture preserves producing AI Participant separately from provider role, partial/final/unavailable completeness, generation and known local sequence gaps. Default capture does not retain provider references or attachment URLs. Capture has finite item/byte bounds and reports omissions; it never claims complete history. Invalid raw builder data falls back to a metadata-only Session outcome. The complete pending intent is still process-local until Connect journal installation.

The named capture policy sets independent metadata, transcript, recorded-media and provider-reference retention. Selected message/agent rules persist their own metadata/content limits. Raw builder sources remain unattributed and cannot grant any audience; source categories still retain the installation limits. An external audio URL alone never sets the captured-audio fact. Physical expiry and selective revision redaction remain separate required implementation work.
