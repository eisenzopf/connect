# Native reliable data

G6-020's native adapter composes reliable data with the existing authenticated envelope-v2 actor and signed physical writer. Production Connect Session-scoped message/journal and public negotiation installation remain separate unfinished work; this SPI is not a business or remote delivery receipt.

`NativePhysicalBinding::with_data_handler` installs one bounded queue alongside the application's subscription delivery future. The unselected application future remains owned across calls. Data uses the same physical lifetime, writer and request quota, with capacity and scheduling reserved for control. The installed actor must have capacity for both control and data.

`configure_native_media` and its held-control variant install one persistent controller and an atomic RTP/data backend. Negotiators must validate exact canonical scope/correlation, capability intersection and observed readiness. Unsupported families fail before either backend prepares resources. Data consumes the same monotonically allocated physical handle space as RTP but never registers an RTP route. WSS supports the data family without a fabricated datagram resource. Data streams expose guarded metadata; raw frame channels remain unavailable.

A recipient data origin can be sealed only from its own current authenticated invocation and exact native route. It binds the physical peer, Core controller pointer, membership/endpoint, wire scope, credential revision and complete credential claims. It retains no old grant and waits for the original command's writer guard to leave before delivery. Its lifetime follows credential/task expiry and authenticated incarnation. An unchanged reoffer reuses the origin, preserving existing data writes.

`publish_data` accepts canonical `message.send`, preserving the logical message and operation IDs, original audience, MIME type and bytes. It checks exact Connection scope, optional authoritative sender, reliable-ordered profile, canonical base64 and the 64 KiB decoded limit; empty text/binary is valid. Attachments and reply-message references are explicitly unsupported in this stream profile. Ignored wire extensions are removed from outgoing execution values. Each delivery gets a fresh wire/signature ID while retaining logical identity; only the recipient's negotiated scope and stream label are projected.

`MediaPolicy::current_data` still defaults to refusal. `native_data_message` exposes sealed facts for an installed policy to validate against current resource/actor/audience/key authority. Held source publication derives its view from the same invocation proof; forwarding and dequeued delivery acquire fresh owned grants. Immutable audience exclusion uses `NotRecipient` and removes only that destination, so an unaddressed subscriber cannot block later messages. Temporary denial and capacity contention remain retryable.

Core queue identity exposes stable IDs and historical source binding for cancellation/recovery, without payload or authority. Route liveness is never a permission check. Retired source/selection generations cancel queued delivery and do not block a replacement publisher. The actual reliable writer claims the one-use `DataWriteGuard` only after its own dequeue. Pending producer cancellation releases readers even if an actor queue retains work. Active IO keeps the real source/recipient readers until its future completes or is dropped. Cancellation classification is conservative around the writer claim; actual touched IO determines physical stream poisoning. A stale item before IO preserves a healthy peer; a possibly partial write reports `SubmissionUnknown` and retires that writer.

The installed data negotiator must idempotently record `NativeDataOutcome` in the application's existing journal/outbox. Outcomes identify the original operation/message, source and target, and distinguish not-started, local-written and unknown. They do not assert remote persistence. Observer failure retains a bounded metadata queue, port cleanup ownership and physical quota until retry succeeds. Shutdown drains the bounded receiver queue into cancellation identities before confirming cleanup.

Per physical peer, the implementation bounds active data ports to 16, retained source payload/original-envelope bytes to 16 MiB, queued writer frame reservations to 8 MiB, and the data mailbox to eight jobs. These are payload/resource budgets, not a claim about total heap usage. Idle queues retain no authorization reader. `writer_submissions` counts accepted bounded physical mailbox attempts before IO; local writes and unknown outcomes are separate counters. Queue capacity and permission refusal do not acknowledge a dropped message.

Run `python3 scripts/check-gate6-native-data.py` for source-bound local macOS arm64 qualification. The selected cases include actual signed QUIC/WebTransport/WSS data, mixed RTP/data, held publication behind a queued store writer, original identities and recipient labels, audience and recipient/key-authority exclusion/recovery, source retirement, observer retry/quota custody, and actual QUIC flow-control failure/recovery. Policy/readiness/journal observers are controlled fixtures. Production Store media policy, canonical public Session/journal installation, general selectors/subscriptions/negotiation/confirmation/presence and other guarded media transports remain unqualified; no browser render, full workspace, remote/provider, release/performance or publication claim follows.
