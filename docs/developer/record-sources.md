# Session record source integration

G6-027's reusable engine stores source policy and integrity as data. Current read authorization is still required. Session membership never establishes a capture audience.

Both explicit Session end and automatic last-connection end freeze the original outcome before any storage await. The existing teardown future owns the bounded store attempt; no background writer is spawned. Failed or cancelled storage retains the same frozen document for explicit retry, including after the Session has ended. A later builder edit or changed end reason cannot rewrite it. Automatic outcomes retain the terminal class (normal, cancelled or failed); private adapter error text is excluded.

Actual adapter connected/ended/failed observations and local participant admission/retirement commits create bounded connection-lineage sources before live ownership is removed. Attribution and ordinary lifecycle capture share the local registry/lifecycle/session fence. Checked participant admission adds the canonical appearance. Managed replacement records retired/admitted sources with the same operation correlation. Local retirement never claims provider hangup or remote delivery. Lineage has opaque stable source IDs, separate metadata retention, and default installation-policy audience. Producer/connection/correlation fields are projected only when the producing party is visible. An absent authoritative event subscription does not disable baseline capture. Capture bounds and omissions remain explicit.

`RecordCapturePolicy::canonical_source` explicitly selects canonical builder sources and freezes their original audiences and independent retention. Unselected raw sources grant nobody access. `connection_audience` classifies baseline metadata. `agent_provider_references` separately selects actual reported provider session/event IDs; ordinary transcript selection never implicitly captures them. Provider references retain actual source attribution, an independent retention decision, `provider-reported` verification and `not-attempted` remote deletion. They do not prove provider delivery or erasure. These synchronous policy callbacks must be pure, bounded and must not reenter Core while its ownership fences are held.

The default view is unsigned. To configure signing, the trusted current `RecordViewLease::sign_projection` returns a `RecordSignature` containing JWS output, an independently selected trusted verification key/algorithm and a bounded signer identifier. Core accepts only a signature over the exact post-filtering payload and verifies every signature with that trusted key. It refuses altered signatures, another payload, a different algorithm or configured signing failure. It never falls back to unsigned delivery after a signing error. Certificate-discovery metadata supplies no trust. Deterministic signing preserves conditional and expiring-reference view hashes. The advertised content hash names the actual delivered JWS bytes; the verified payload remains the caller-authorized vCon. Readiness reports verified signer identifiers and no encryption. Full-record signatures are never borrowed for a projected view. JWE and protocol E2EE are not implemented.

The local qualification runs actual Core, canonical peer and owned Postgres behavior, independently validates exported records against the selected schema and checks an actual delivered RS256 JWS using OpenSSL and the pinned public fixture key. It includes the automatic end/store-failure recovery path, explicit inline media/transcript projection, separately selected provider references and blocked signed response IO. `scripts/check-gate6-record-sources.py --local-postgres` reproduces this profile. Production Connect authority/journal installation, restart recovery of host pending intents, retention scheduling and public HTTPS/native routes remain the downstream tasks named in the plan. This profile does not qualify remote providers, Linux x86_64 hosting or Gate 6 acceptance.
