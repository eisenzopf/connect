# Original private SIP candidate host

The configured initial telephone host now supplies the protected consultation
coordinator's SIP candidate path. It resolves the original admitted target and
uses that identity's installed Endpoint/route policy. Candidate metadata names
its actual `native` or `sip` reservation kind; a SIP reservation does not borrow
a native registration or cause a provider initializer to create another peer.

The host reserves one private canonical Connection and child operation from the
original consultation. Its bounded job owns the actual Core outbound ticket,
planned SIP Call-ID and cleanup. Concurrent initialization/replay shares the
same job result. A watch contains the actual owned leg, not an authority reader
or an IO permission. Before returning the reserved ID, the host rechecks the
actual private admission receipt and obtains/drops a fresh current private
admission interval. It cannot redial from an old watch or substitute the target's
already public call.

The call uses `activate_private_initial_participant_with_held` on that original
ticket. It captures the actual SIP answer and separate own private consent,
obtains the [private admission reader](private-sip-candidate-readiness.md), and
builds its guarded controller from the exact Core outbound preparation and
negotiated SIP ports. It prepares audio at revision one and mutes it at revision
two before Core's final fresh `PreparePrivateAudio` quarantine/admission. The
private mode and original logical mutation remain sealed. Ordinary public
activation, consent or readiness cannot be a fallback.

The installed ready observer attests original private Core mode, Participant
admission, committed guarded proof, exact controller and unchanged negotiated
binding. Only then does the Store record private connected custody and the job
report ready to its coordinator. The completed child does not complete its
consultation root or authorize a private audience switch.

An authority-busy or storage-unavailable metadata probe retains only this
already closed original quarantine and retries under the original deadline.
It returns no cached permission or new IO grant. Packet guards continue to
refuse until fresh authority is available. The coordinator's watch revalidation
uses the same bounded metadata retry; it does not allocate or signal again.

The current lifetime after this admission is deliberately bounded quarantine.
It installs no ordinary public receive programme, subscription projection or
DTMF listener. Fresh original execution/route authority, original expiry and
actual call liveness remain required. Session/host shutdown, root cancellation,
expiry or withdrawal ends only the original private call and records captured
absence. Possible submission prevents false root failure; known cleanup can
settle cancelled/failed initialization without claiming an audience rollback.

The coordinator's scene planner still selects only native candidates. Typed
SIP-candidate source/selection, a sealed continuing private lifetime independent
of the ended execution credential, actual private media/INFO/RFC4733 and return
remain required. An admitted quarantined call is not private consultation
completion. The [host component report](../evidence/gate-6/auxiliary-private-sip-candidate-host.json)
now records both signing algorithms through the actual public client/server,
native and UDP SIP stack. Each fixture establishes positive public audio at
two Participant subscribers, admits a fresh private call beside that same
Participant/Endpoint's original public call, observes zero marked private
audio at both public receivers, holds an authority writer for 250ms without a
BYE, replays without redial and captures exact private cancellation/cleanup.
Marked original public audio still flows afterward. This qualifies the local
quarantined admission/cleanup component, not private switch/DTMF/return or a
complete G6-046 clause. Earlier SDK Identifier, public-baseline readiness and
premature authority-busy lifecycle failures are preserved separately.

`Service::prepare_private_sip_consultation_candidate` exposes the same protected
composition to server initializers over an already admitted origin. It adds no
wire permission or endpoint. Clients continue to use the existing consultation
and operation methods in the [server HTTP reference](canonical-http.md).
