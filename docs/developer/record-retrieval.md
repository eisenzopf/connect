# Canonical record retrieval

G6-027 remains in progress. The reusable retrieval profile uses an exact owner-scoped local index lookup and one retained read of the current revision. UUID and local location selectors must identify the same record when both are supplied. A requested URL is never fetched over the network. Postgres verifies the indexed UUID against the actual canonical document.

`recording.vcon-fetched` includes `content_hash` over the exact authorized projection bytes. Inline and URL deliveries are exclusive; URL delivery requires expiry. Requests and replies carry Conversation/Session scope. Published schema/vectors and shared Rust payloads define these fields. Projection correlation is stable for the record revision, so an unchanged permitted view can be fetched with its prior digest using a fresh signed envelope. The envelope's reply correlation still identifies the actual command.

The trusted backend calls `authorize_record_fetch` under the original current credential/resource grant, deriving viewer and scope from that verified binding. Its source-policy callback derives permission under the same held guard and does not reacquire a reader behind a queued writer. The returned `AuthorityLease` owns `RecordFetchCustody`, which contains both that original grant and the projected record read. The canonical peer already retains this lease through actual response IO. `RecordFetchHandler` checks exact invocation and principal ownership; a body/hash or matching Session never grants access. Missing records, failed storage and changed projected digests produce explicit correlated errors without private backend text.

Readiness data contains only the authorized UUID/revision/view digest, explicit verified signer identifiers and an unencrypted flag; it exposes neither a backend location nor a full source/manifest digest. Readiness never proves captured audio exists.

Small views are inline. A configured bounded `RecordReferenceRegistry` issues expiring HTTPS references containing data only: no bytes or authority reader are held while waiting for retrieval. An adapter authenticates each retrieval again, derives current scope/viewer and uses `retrieve` with a fresh current source grant. It checks exact scope, viewer, original record revision/digests, current audience, current view digest and expiry before releasing data. A URL alone, revoked source audience, changed record, expired reference or unrelated current grant cannot borrow the old permission. `GuardedRecordBody` retains both grants through the actual body write and checks cancellation/deadline between bounded chunks. Completion means local IO submission, not a remote receipt.

The registry is process-local and capacity-bounded; restart loses references. Configured media URLs still need their own current authorization on retrieval. This increment does not install a Connect HTTP route: G6-037/G6-038/G6-046 own the production current-authority/journal/service and public HTTP/native integration, with its server reference. Explicit source capture and verified projection signing hooks are described in `record-sources.md`; complete Gate 6 qualification remains open. The default record profile advertises no signing, encryption or protocol E2EE.
