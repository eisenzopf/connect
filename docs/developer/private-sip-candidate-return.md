# Recorded private SIP candidate return

Schema 109 admits return over the exact original typed applied consultation,
including a SIP candidate. The new return needs its own current named permission;
the ended consultation controller supplies neither permission nor an IO reader.
The database trigger pins the captured private source to its original root,
canonical Connection, initial child, Core connection, SIP Call-ID, own consent,
Endpoint and Participant epoch. A previously captured departure remains usable
without borrowing a current route grant or inventing a native lifetime.

A live private SIP candidate receives a distinct return closure reader inside the
complete fresh return interval. It cannot receive media and gets no send/receive
pair with any native participant. Only the original private candidate can obtain
this view; missing, duplicate, foreign and public-sibling substitutions fail.
The original native primary/remote can have purpose-bound restored routes. A
cloned closure reader retains the whole authority interval, including the route
owner's scope, until it is dropped. Withdrawing candidate receive permission
does not require reopening its consulting media grant just to close it.

One exact restoration attempt and its captured outcome update only the original
observed stream revisions and release the primary's private floor. An uncertain
attempt keeps both original private floors and cannot submit again. Return
completion waits for the original SIP call's captured absence, using its typed
historical binding rather than a native retirement row. A wrong absence observer
cannot settle it; an already captured original departure need not be recreated.
The candidate Participant's public native sibling is not retired. Historical
recording and completion can survive the return credential ending, but cannot
authorize fresh work or be reused by another runtime.

These are controlled Store admission, planning, recording and retirement checks.
They do not qualify actual private SIP/Core audience restoration. The installed
SIP audience control dispatcher recognizes the original candidate's restore role,
but the coordinator still selects native candidates and the private SIP owner,
packet and host lifetime paths still use bounded admission. Complete pending and
established media/signal/lifecycle intervals, unrelated private SIP group
preservation and actual private audio/INFO/RFC4733/return/cleanup remain required.
Named DTMF permissions must remain independent of codec/subscribe/offer rights.
No Gate 6 clause or task closes from this component. The existing consultation
and operation methods in the [server HTTP reference](canonical-http.md) remain
the public client interface.
