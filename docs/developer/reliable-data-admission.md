# Typed reliable data admission

This G6-020 increment supplies Core's guarded handoff to a future native reliable writer. It does not yet install that writer, a native data negotiator, a public Session-scoped message handler, or a durable message receipt. Gate 6 remains in progress.

`StagedData` carries a validated reliable-ordered `DataMessage` and immutable application context through publication, scene fan-out, backpressure and queued delivery. The context can preserve the canonical operation ID and original audience; it is not an authorization grant. Retry preserves the original message ID, bytes, label, MIME type and context. Source and receiver logical labels can differ; the target binding identifies the receiver.

Typed publication, forwarding and dequeued delivery call `MediaPolicy::current_data`. Its default refuses the operation. An installed implementation must validate the exact message and application context, current actor, membership, resource scope and per-message audience. It must return an owned current guard. Generic stream-control permission cannot substitute for message permission. The optional held context is available only at source publication, where policy can derive the exact invocation's authority without reacquiring its store. Forwarding and each delivery attempt acquire fresh authority. Idle queues retain metadata, never the publication grant.

Adapters can require typed messages while preparing a data port. Those ports refuse contextless frames and publication/delivery outside active managed-scene admission. Data uses no RTP payload type or clock. The data limit is 64 KiB, matching `DataMessage`; empty text and binary bodies are valid, while JSON and UTF-8 checks follow the negotiated protocol.

`QueuedMedia::admit_data` returns one fresh `AdmittedData` attempt. A producer retains `cancel_on_drop()` while another queue owns copies of the attempt, and monitors `cancelled()`. Pending producer cancellation or observed deadline/retirement releases current source/recipient readers even if the physical actor has not dequeued the item. Each attempt is capped at 200 ms and the earlier credential/task expiry. The original ordered message remains available for a fresh attempt after capacity contention or an attempt deadline; this does not silently expire the message.

Only the actual writer calls `begin_write()`. Exactly one caller can obtain its non-cloneable `DataWriteGuard`. After this transfer, producer cancellation wakes the writer but cannot release authority beneath ongoing IO. The writer must retain the guard until its awaited write completes or its IO future is actually dropped. Port and subscription drains use those same delivery guards. Temporary quiescence permits admitted IO to finish; permanent route retirement and scene departure cancel it. A receiver origin must additionally verify exact controller ownership, authenticated physical incarnation and credential revision before queueing; target IDs alone are insufficient.

This API deliberately returns no transport submission result or business ACK. The native writer integration must distinguish refusal before IO from uncertainty after a write may have started, retire a poisoned physical writer, and preserve stable operation/message identity for the application's existing journal/replay path.

Run `python3 scripts/check-gate6-reliable-data-admission.py` for the source-bound local macOS arm64 qualification. It repeats the selected previous scene/audio/native RTP regressions and adds controlled-policy Core cases for typed context, size/encoding, ordered backpressure, current audience, held publication behind a queued store writer, pending cancellation, active writer custody, concurrent claims, deadline, terminal callbacks, departure, drain and callback abortion. Native reliable transport and production policy/journal installation remain unqualified.
