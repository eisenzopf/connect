# Guarded private SIP candidate readiness

After [own answer consent](private-sip-candidate-answer.md),
`Store::try_private_initial_telephone_admission_read` obtains a short authority
interval for the original quarantined candidate. It rechecks the same
consultation, reserved Connection, controller execution, Endpoint/Device,
original member epochs, own consent and independent route. Its codec comes
from that exact observed private answer. It neither changes nor borrows public
Session codec acceptance. Ordinary media and signal reads still refuse this
private origin.

This is bounded admission authority. The original child and consultation must
remain uncancelled and within their original expiry; the root must be accepted,
unclaimed and have no audience attempt. The same original candidate can be read
after its connected fact is recorded, without turning its reservation into an
unused allocation again. A claimed root, stale epoch, replaced Endpoint,
withdrawn grant or expired preparation refuses the read. It is not the
continuing authority of an established private scene. Dropping the read releases
the complete original execution audience and route fences.

`Store::record_private_initial_telephone_connected` accepts the separate
`PrivateInitialTelephoneRuntimeObservation` trusted backend boundary. The
service's `initial_telephone::policy::Ready` attestation checks actual private
Core preparation mode, original Participant admission, committed guarded media
proof, current original controller ownership and exact negotiated physical
binding. Private admission requires the muted revision-two controller; ordinary
public readiness rejects private Core mode. A caller-supplied wire body cannot
provide either observation.

The Store checks the exact original runtime Connection, SIP Call-ID,
Participant/epoch/generation, guarded stream revision and logical stream. It
captures twice before committing so a changed observation rolls back the whole
ready fact and its journal events. The completed child does not claim or
complete the consultation root. Its `connection_ready` event goes only to the
two original private members. It does not populate public Session readiness,
activate the public Session, announce a public join or extend public reconnect
coverage. Public media/readiness APIs remain unavailable to this source.

Schema 107 additionally binds private connected JSON to the original typed
consent, child/root, physical IDs, Endpoint/Device, member epoch, observed codec,
generation and quarantine revision. It refuses ordinary public readiness JSON
or a different private incarnation. This is fresh pre-alpha initialization;
older stores are refused without automatic migration. Actual original cleanup
can still be recorded after permission withdrawal. Historical quarantine
capture survives backup, while old runtime handles grant no restored readiness.

The [component report](../evidence/gate-6/auxiliary-private-sip-candidate-readiness.json)
records controlled trusted-observer Store checks and compilation separately
from physical transport evidence. The [original private SIP host path](private-sip-candidate-host.md)
now installs private activation, the guarded callback, muted ports and Core
`PreparePrivateAudio`; its new socket checks are pending. It still requires typed
candidate selection/lifetime, actual private media/DTMF, return and physical
cleanup. These Store cases do not qualify that complete host or SIP wire path.

No public HTTP method is added; the
[server HTTP reference](canonical-http.md) retains the existing methods.
