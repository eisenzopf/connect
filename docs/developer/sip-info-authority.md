# Owned SIP INFO writes (G6-024 in progress)

`UnifiedDialogApi::send_info_with_options_authorized` uses the existing immutable INFO snapshot and sole request materializer. It installs a `ClientRequestWriteAuthority` before the transaction is published. The policy receives the actual transaction key, immutable request and prepared transport route at the common first-send and Timer E retransmission boundary. Those facts grant no permission. The trusted host must acquire current independent source/recipient permission for each write and retain its owned guard through the supplied IO future, including abortion. It must not detach transport work or retain permission between retries.

`OwnedInfoDelivery` retains a `ClientRequestWriteOwner`. Keep the delivery alive while observing its exact completion. Dropping it, cancelling it or reaching its absolute deadline aborts pending owned IO and refuses subsequent retries. A synchronous fence serializes cancellation with bounded physical IO polls and releases on Pending; permission acquisition and response waits run outside that fence. Refusal before the physical future's first poll does not mark a first write as attempted. An error after that boundary can leave an uncertain effect and must never authorize replay of a logical operation.

Guarded INFO uses one exact transaction. Its transport retransmissions keep the same branch, CSeq, entity and request bytes and acquire fresh permission. It does not fail over to another address candidate or schedule an authentication retry. A 401 is an exact final SIP response. A 200 is transaction evidence, not proof that the peer played a tone. Existing general standalone SIP APIs retain their separate behavior; they are not the qualified Gate 6 routing path.

`scripts/check-gate6-sip-info-authority.py` runs the new actual UDP public API checks and affected transaction manager, client, exact-completion and canonical-materializer regressions, then checks the locked Connect server build. Fixtures use isolated local ephemeral sockets. Controlled Pending IO tests prove guard custody and that cancellation or expiry prevents a later ready write. The qualified network profile is UDP. Other transport implementations require their own physical IO ownership evidence.

This component does not close G6-024. Core method-specific INFO policy, the exact current SIP adapter lifecycle and endpoint profile, sealed native/SIP/WebRTC source and egress composition, remaining approved media profiles and the downstream production journal/service/HTTP/SDK installation remain open. Gate 6 platform and named remote acceptance remain separate.
