# Current-authorized DTMF routing

G6-024 remains open. This component replaces Core's raw bridge auto-forwarding and target-only `send_dtmf` API. An adapter observation still produces attributed local events; it never starts a tone schedule. A bridge or media grant is not independent signal permission.

A trusted backend creates an immutable `DtmfIntent` with the original logical operation ID, complete digits, duration and requested method. `Orchestrator::prepare_dtmf_route` captures exact live source and recipient Connection generations, Participants, Sessions, Conversation, Tenant and transports. Missing or unrelated endpoints refuse before effects. These snapshots carry data, not permission. Cross-Session routing within one Conversation still requires explicit policy for both endpoints.

`route_dtmf` owns and awaits one bounded schedule. Its `DtmfRoutePolicy` acquires actual current source/recipient permission for every physical RTP packet, including final event repeats. The scope contains the exact original operation and full intent plus the actual negotiated RTP write metadata. The policy must derive the authenticated actor, current credentials and relationship epochs from its real host context; a supplied Connection ID cannot establish them. A policy must reuse any actual held domain without reader reentry behind a queued writer. It must not cache a policy reader between packet ticks or interdigit gaps. Default policy refuses.

An owned `DtmfWriteLease` retains current permission through actual IO. A bounded synchronous `DtmfIoFence` surrounds each IO future poll, retaining Core's registry, exact lifecycle and Session/Conversation readers only for that poll. This serializes physical IO admission with local retirement without retaining a non-Send lock across suspension. A Pending poll releases these synchronous locks while retaining its owned host grant until IO completes or is aborted. Withdrawal prevents later polling of a now-ready socket future. Transport IO and fence callbacks must be bounded and must not reenter Core. Additional physical source fences carry no permission and must not retain idle grants.

There is one active schedule per recipient Connection and at most 64 per Core instance; admission uses no unbounded waiter queue. Caller cancellation, current source/recipient loss and one absolute deadline stop the owned future. The deadline is bounded by the complete-sequence 30-second profile and is not renewed by packet progress. Invalid complete sequences and unsupported methods cannot submit a valid prefix. An error after any IO poll is conservatively unknown; already submitted packets cannot be erased by later refusal. Dropping the caller future stops the suffix. Success describes local submission, not remote tone consumption or a durable service receipt. Core never retries a logical operation; the host journal must reconcile original intent and uncertainty before another effect.

The current Core transport adapter route selects RFC4733 explicitly and uses the existing authorized RTP primitive. INFO returns Unsupported before permission acquisition or any RTP fallback. Real SIP INFO per-write/retransmission authority, richer SIP/WebRTC source observations and composition with sealed native origins/egress remain required G6-024 work. The lower transport APIs remain separate trusted primitives; their existence does not qualify the public gateway path. Production Connect journal/service/HTTP/SDK installation and Linux/remote/native/browser/provider acceptance remain downstream work.

Local tests use real Core Session bindings and UDP RTP, inspect dynamic payload 110 and the actual SSRC/event bytes, and exercise independent refusal, revocation between packets, source-only retirement, deadlines, cancellation/drop, target contention, unrelated Conversation refusal and absence of raw fallback. A separate controlled IO future proves Pending releases the synchronous fence and retirement prevents subsequent ready IO while retaining the host grant through abortion. `scripts/check-gate6-dtmf-routing.py` also repeats the affected audio/RTP/SIP/WebRTC regressions and locked server compile check. The exact pre-fix unauthorized adapter call is preserved privately as failure evidence.
