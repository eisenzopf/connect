# Private SIP candidates in a complete scene

The consultation coordinator selects one registered candidate from the current
native and SIP scene. A SIP candidate must be the original private initial child
of the requested consultation, with the same reserved canonical Connection,
primary, controller, intent digest and runtime. Current original physical facts
are checked before it can match. Public initial calls, established calls and
private candidates of another consultation cannot substitute for that child.
The coordinator passes the candidate's actual Core connection to the audience
planner and retains the original owned call through the switch.

A separate established private SIP group keeps its own current-media context.
The new consultation's controller cannot lend authority to that group. The
complete interval covers each group's original physical and private context
scopes, and each SIP reader retains that interval. Reciprocal physical partner
checks preserve the existing pair without adding cross-group or public sibling
edges. A return grants closure control only to its own candidate; unrelated
private groups retain their current-media context and original pair.

These changes do not provide AI provider readiness. Existing current provider
checks still apply, and a private SIP preparation cannot stand in for a live
provider context. Controlled Store scene tests and service compilation are
separate from actual socket qualification. Actual reverse SIP-candidate media,
INFO/RFC4733, permission recovery, replay, sibling exclusion and return remain
open until observed. This does not close G6-046.

Public commands use the existing [server HTTP reference](canonical-http.md).
