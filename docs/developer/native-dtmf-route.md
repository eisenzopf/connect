# Native DTMF source routing (G6-024 in progress)

`NativeDtmfObservation::prepare_core_route` binds actual signed QUIC/WebTransport ingress to an explicit Core DTMF route. The observation preserves the original operation, digits, duration and requested method, together with the authenticated principal, verified signing-key ID/algorithm, relationship identities, actual transport, credential revision, stream bindings and physical flow epoch. `payload.source` cannot change those facts. The sealed origin verifies the exact registered adapter; metadata from another Core or an unsealed native route cannot schedule an effect.

This binding supplies source metadata and physical custody. It supplies no permission. After the signed ingress invocation finishes and releases its readers, the host journals/deduplicates the original operation and supplies fresh independent source/recipient signal authority for each actual INFO or RFC4733 write. That authority must check the exact observed signing key remains current, current principal/relationship epochs, intended recipient and immutable intent. Media permission cannot substitute for signal permission. No original envelope, signature bytes or invocation lease is retained in the observation.

Core's source fence now requires a synchronous physical IO poll hook; its default implementation refuses. A `current() == true` metadata hint alone cannot authorize a write. Core holds its exact registry/lifecycle/Session/Conversation custody while the native source fence tries the actual flow, controller, credential and audio-port metadata locks. It verifies the original confirmed flow epoch, stream revision, credential revision, physical peer binding and active exact audio handles. All nested metadata locks use try-locks and release on Pending. Temporary contention defers IO within the original bounded deadline; it never supplies permission. Retirement/rebind/reoffer cannot revive an old observation by restoring a revision number.

The existing owned SIP INFO and negotiated RFC4733 writers carry this source fence through each actual transport poll. Retries obtain fresh signal permission and remain part of the original operation. Once any prefix may have reached IO, a later refusal or source closure remains `OutcomeUnknown`; the host reconciles the original operation. Success proves local submission, and a SIP 2xx proves SIP acceptance. Neither proves remote tone playback.

`scripts/check-gate6-native-dtmf-route.py` uses real signed TLS QUIC/WebTransport ingress, actual native Participant admission, actual SIP/SDP calls in a separate Session of the same Conversation, UDP INFO and negotiated RTP telephone-event packets. It verifies original intent, payload-source rejection, source/recipient/key revocation without idle readers, physical peer closure, source stream retirement, reoffer epoch replacement, refusal after fresh permission but before physical IO, pending-poll guard release, missing signal authority and mismatched Core/recipient metadata. The retained pre-fix regression records real RTP effects authorized by a metadata-only source hint. All endpoints and policy stores are isolated local fixtures.

The separate [Core native-recipient profile](core-native-dtmf.md) extends scheduling to native recipients. Enriched received SIP/WebRTC source composition, the remaining approved media profiles and full G6-024 remain open. Production journal/service/HTTP/SDK installation belongs to G6-037/G6-038 and dependent work. Linux x86_64 and named remote/browser/provider rehearsals are separate qualification scopes.
