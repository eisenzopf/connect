Build Parley through Connect.

A developer should install Connect, create a conversation, add people and agents, exchange private messages, start live sessions, consult, hand off and move between devices through a small public SDK. The application keeps its domain workflow and UI. Connect supplies the reusable communication behavior.

Agent buildersGive an AI participant useful context and observable communication tools; integrate their own model, prompts, scheduling and approval policy.
Operators and contributorsDeploy a supported server, add endpoints/connectors, and implement an interoperable client from published specifications and vectors.

Product test: a complete reference app uses only public Connect SDKs for communication. Its worker owns the travel scenario and decisions; Connect owns authorized execution, durable state and media orchestration. The same communication sequence works with local fixtures and separately qualified real providers.

Three journeys prove the product.

Journey 1 · First conversation

Install. Send. Receive.

  1. Install a versioned SDK and local server; run one setup command with no provider account.
  2. Create human and AI/app identities and a conversation; send a private typed message and file.
  3. Receive a correlated reply, restart and recover history through the same public API.
  4. Add local voice/video and inspect explicit capability and operation states.
Journey 2 · Hosted application

Bring your own application.

  1. Install the supported Linux server with TLS and scoped endpoint enrollment.
  2. Connect a remote browser and native client, using WebTransport or the explicit WSS/WebRTC fallback.
  3. Provision real AI/telephone/message endpoints from a trusted backend.
  4. Operate, diagnose, back up and restart without changing app communication logic.
Journey 3 · Parley-style continuity

One conversation, through the whole interaction.

  1. Talk with the AI assistant in the browser; retain the task context and attributable messages.
  2. Contact an organizer privately by message and telephone; distinguish acceptance, delivery, reply and audio readiness.
  3. Keep the organizer connected while the AI consults privately with the owner. Excluded participants hear no consultation audio and receive none of its private context.
  4. After the application’s consent decision, admit the owner and hand over the speaking role while retaining the organizer Connection and main Session.
  5. Move the owner from browser to a provisioned phone after answer, configured endpoint confirmation and verified media readiness; preserve the existing route on failure.
  6. End voice and continue messaging with the outcome in the same Conversation. Recover lost replies or restart without duplicate calls or invented live state.

An additional contributor journey installs a new message/live-media connector and implements a separate UCTP client from the public kit. All journeys include refusal, cancellation and recovery, not only the successful sequence.

Keep six nouns. Define the behavior between them.

The model is sufficient for Parley when lifecycle rules and supporting concepts are precise. Handoff and consultation are operations over existing nouns; a business task and its approval policy stay in the application.

This is a proposed shared state vocabulary, not an invented claim of distributed atomicity. Each operation defines legal edges, cancellation cutoff, expected revision, timeout and reconciliation. A carrier submission or live-media commit cannot be rolled back merely by reverting a database row.

  • Preserve the old usable path until the new path is ready; an offer, SIP answer or accepted API call alone is insufficient.
  • A stale controller cannot overwrite a newer handoff. Concurrent operations conflict or serialize according to the frozen contract.
  • Use fresh signed transport envelopes with a stable logical operation ID; identical retry recovers status, changed content conflicts.
  • Unknown provider outcomes require reconciliation. Do not redial because a local response was lost.
  • Audience filtering applies to events, history, attachments, recordings, receipts and AI projections, including after membership changes.

A dedicated server HTTP API reference.

The server HTTP/JSON interface is a supported entry point for backends, automation, provisioning, message/file workflows and observing long-running operations. Developers should be able to use it directly with curl or an HTTP client. UCTP defines the shared conversation semantics; HTTP calls enter the same authorized service.
