Product & delivery plan

Reach your assistant.
Let it call you back.

Vapi chat and two-way Telnyx telephone voice through Connect. Live SMS deferred until approval.

DocsOutcomeDesignAcceptanceImplementation

An assistant people can message and call.

Give a Vapi assistant a Connect identity, reach it through the SDK, and use an owned Telnyx number for telephone calls in both directions.

Reach out.

An application or agent sends a chat message or starts a telephone call through Connect. Vapi supplies the assistant; Telnyx supplies the number and SIP/PSTN access. Connect records the accepted command and tracks its outcome.

Be reachable.

A person calls the Telnyx number and reaches the assigned Vapi assistant. A configured inbound route maps the provider call to the right Connect conversation. Unknown or ambiguous callers are never guessed into an existing private conversation.

The experience to prove.

  1. Start one local Connect server with persistent state, scoped credentials and explicit TLS trust.
  2. Configure the isolated Vapi assistant, Telnyx native provider credentials, number and inbound route (BYO SIP remains an alternative). Reuse owned checkpoints; do not create replacement numbers on retries.
  3. Use Python and TypeScript to continue a real Vapi chat through the same Connect conversation.
  4. Use a public SDK to call the authorized test handset, confirm caller ID and exchange audio with the assistant.
  5. Call the owned number from the handset; confirm assistant audio and view the correlated inbound call through Connect.
  6. End a call, restart local clients/server and recover receipts, status and journal events without redialing.

One assistant configuration does not automatically transfer history between chat and voice. Explicit conversation and provider-call mappings are required; automatic model context transfer is not claimed.

Separate telephone media from Connect control.

SDK / HTTP / UCTP-QUIC → Connect → Vapi call control
Telephone ↔ Telnyx SIP/PSTN ↔ Vapi assistant audio

Connect owns scoped commands, durable acceptance, idempotency, route bindings, provider correlation and observable call state. Vapi runs the voice assistant and telephone media over the configured Telnyx SIP connection. Native audio datagrams through Connect and browser WebRTC are Gate 3 proofs.

The initial inbound implementation may reconcile calls through authenticated Vapi API polling. It must be bounded, deduplicated, explicit about delayed visibility, and restricted to configured phone/assistant/caller bindings. A provider callback interface can replace or supplement polling later without changing conversation semantics.

What belongs to this gate.

Required

  • Rust, Python, TypeScript and HTTP/JSON communication surfaces.
  • Real Vapi chat, outbound telephone audio and inbound telephone audio.
  • Telnyx number/provider setup with readback, recoverable checkpoints and preserved messaging settings.
  • Durable call status/end, provider IDs, journal events and safe replay/recovery.
  • Local SMS implementation and fixtures remain tested.

Explicitly separate

  • Live SMS and signed real SMS callbacks are deferred pending approval, at the owner’s direction.
  • Native QUIC audio and browser WebRTC remain Gate 3.
  • MCP, skill, additional assistant, files, video and reference client remain in the v0.1 roadmap.
  • Presence/endpoint preferences remain decision B-001.
  • No remote Connect deployment or new public package is required here.

Deliver in five reviewable steps.

  1. D2-01 — Foundation: G2-001–009; durable messaging/provider boundaries and local recovery.
  2. D2-02 — SDK and chat: G2-010–015; public clients, example and real Vapi context.
  3. D2-03 — Telephone setup: G2-016–017 and G2-022; owned number, native Telnyx call route and inbound Vapi routing.
  4. D2-04 — Telephone behavior: G2-021, G2-023, G2-025 and G2-027; durable control, inbound correlation and both live audio directions.
  5. D2-05 — Qualification: G2-020; offline suite, live evidence, deferred SMS record and usable runbook.

The finish line.

Setup and call-state records do not prove audio. Required live criteria need a real conversation and correlated evidence.

Latest stabilization and review handoff. The following live evidence predates stabilization; no new calls were placed during that pass.

The full local suite passes 74 workspace tests/doctests, pinned upstream regressions and all process recovery checks. Both language clients resumed real Vapi chat context after installed-server restart. The installed package passes all ten checks. The owner subsequently called in and confirmed the assistant answered; provider records two human turns and one assistant turn, correlated to the same Connect conversation. No independent audio-quality measurement is claimed. Live SMS stays owner-deferred.
